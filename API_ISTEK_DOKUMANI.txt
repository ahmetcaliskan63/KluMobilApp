======================================================================
     KLUMOBILE APİ ENTEGRASYON VE VERİ SÖZLEŞMESİ (NİHAİ REHBER)
======================================================================
Bu döküman, KLUMobil uygulamasının backend (sunucu) tarafında hazırlanması 
gereken tüm servisleri, veri yapılarını ve mantıksal gereksinimleri içerir.

----------------------------------------------------------------------
1. GENEL TEKNİK STANDARTLAR
----------------------------------------------------------------------
* Protokol: HTTPS / RESTful API
* Veri Formatı: JSON
* Kimlik Doğrulama: Tüm isteklerde 'Authorization: Bearer <JWT_TOKEN>' zorunludur.
* Çok Dilli Yapı: Veriler, Header'daki 'Accept-Language' (tr/en) değerine göre dönmelidir.
* Standart Yanıt Yapısı:
  {
    "success": true, // İşlem durumu
    "message": "İşlem başarılı", // Kullanıcıya gösterilecek mesaj
    "data": { ... } // Asıl veri içeriği
  }

----------------------------------------------------------------------
2. KİMLİK DOĞRULAMA (AUTH)
----------------------------------------------------------------------
Endpoint: POST /api/v1/auth/login
Açıklama: Kullanıcı adı ve şifre ile sisteme giriş yapar.
Yanıt Örneği:
{
  "token": "JWT_TOKEN_ALANI",
  "user": {
    "id": "user_101",
    "role": "student", // 'student' (öğrenci) veya 'academic' (akademisyen)
    "firstName": "Ahmet",
    "lastName": "Çalışkan",
    "department": "Yazılım Mühendisliği",
    "studentNumber": "1200505001",
    "profileImage": "https://url-to-image.jpg"
  }
}

----------------------------------------------------------------------
3. ANA SAYFA VE SOSYAL (DASHBOARD)
----------------------------------------------------------------------
Endpoint: GET /api/v1/dashboard
Açıklama: Ana sayfadaki Haberler, Duyurular ve Etkinlikleri döner.

A) HABERLER (News):
- { "id", "title", "content", "image", "date", "location", "views" }

B) DUYURULAR (Announcements):
- { "id", "title", "content", "snippet", "category", "date", "views", "isRead" }
- Kategori Tipleri: 'academic', 'social', 'general'

C) ETKİNLİKLER (Events):
- { "id", "title", "date", "time", "location", "organizer", "type", "image" }

----------------------------------------------------------------------
4. AKADEMİK BİLGİ SİSTEMİ (OBS)
----------------------------------------------------------------------

A) DERS PROGRAMI (GET /api/v1/academic/schedule)
- Veri: { "id", "code", "name", "instructor", "day", "startTime", "endTime", "location", "room", "color", "syllabus": ["Konu 1", "Konu 2"], "attendance": 92 }
- Syllabus: Dersin haftalık işlenen konuları (Dizi/Array).
- Attendance: Derse katılım yüzdesi.

B) SINAV PROGRAMI VE SONUÇLAR (GET /api/v1/academic/exams)
- Veri: { "courseName", "type" (Vize/Final), "date", "day", "time", "location", "grade" (0-100), "letterGrade" (AA-FF), "status" }

C) TRANSKRİPT (GET /api/v1/academic/transcript)
- KRİTİK: Veriler dönemlere göre gruplanmış olmalıdır!
- Yapı: [ { "semester": "2024-2025 Güz", "gpa": "3.50", "totalAkts": "30", "courses": [...] } ]

D) DEVAMSIZLIK VE MEZUNİYET (GET /api/v1/academic/status)
- Devamsızlık: { "courseName", "attended", "total", "limit", "risk" (low/medium/high) }
- Mezuniyet: { "completedCredits", "totalRequiredCredits", "completedCourses", "totalRequiredCourses", "gpaTarget" }

----------------------------------------------------------------------
5. PROFİL VE KULLANICI DETAYLARI
----------------------------------------------------------------------
Endpoint: GET /api/v1/profile/me
Açıklama: Özlük bilgileri ve akademik istatistikleri döner.

- personalInfo: { "tcNo", "faculty", "majorBranch", "birthDate", "phone", "address", "registrationDate" }
- academicStats: { "gpa", "totalCredits", "completedCourses", "ects" }
- academicStaffExtras: (Sadece Hocalar İçin) { "staffNumber", "remainingLeave", "publications", "workPhone" }

----------------------------------------------------------------------
6. KAMPÜS VE KURUMSAL REHBER
----------------------------------------------------------------------
A) BİRİMLER (Units): [ { "id", "name", "type", "phones", "email", "website", "address", "location": { "latitude", "longitude" } } ]
B) HOCALAR (Faculty): [ { "id", "name", "title", "department", "email", "office", "avatar" } ]
C) AKADEMİK TAKVİM: 
   - Tarihler: [ { "title", "startDate", "endDate", "type" } ]
   - PDF'ler: [ { "title": "Lisans Takvimi", "url": "https://...", "colors": ["#111", "#222"] } ]
D) KURUMSAL: { "history", "vision", "mission", "rectorMessage" }

----------------------------------------------------------------------
7. KÜTÜPHANE VE YEMEKHANE
----------------------------------------------------------------------
A) YEMEKHANE: { "date", "items": ["Yemek 1", "Yemek 2"...], "calories" }
B) KÜTÜPHANE:
   - Ödünçlerim: [ { "title", "author", "isbn", "dueDate", "status" } ]
   - Servisler: [ { "title": "Katalog Tarama", "url": "https://...", "icon", "color" } ]

----------------------------------------------------------------------
8. YARDIMCI SERVİSLER
----------------------------------------------------------------------
A) BİLDİRİMLER: [ { "id", "title", "description", "time", "type", "isRead" } ]
B) ONBOARDING: [ { "title", "description", "image_url" } ] (Uygulama tanıtım slaytları)

----------------------------------------------------------------------
9. BACKEND EKİBİ İÇİN KRİTİK NOTLAR
----------------------------------------------------------------------
1. İsimlendirme (Key Names): Dökümandaki İngilizce isimlere (Örn: 'courseName', 'isRead') sadık kalınmalıdır. Mobil uygulama bu isimleri beklemektedir.
2. Boş Veriler: Veri yoksa 'null' yerine boş liste '[]' veya boş string '' dönülmesi tercih edilir.
3. Resimler: Profil, haber ve etkinlik resimleri mutlaka 'https://' ile başlayan tam URL olmalıdır.
4. Güvenlik: Kullanıcı verileri (Profil, Notlar vb.) sadece o kullanıcıya ait Token ile erişilebilir olmalıdır.
